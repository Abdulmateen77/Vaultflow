1. Overview

The Vaultflow PII Redaction Gateway is a single-endpoint REST API that detects and redacts personally identifiable information (PII) from arbitrary text. It combines high-recall regex detection for structured PII (email, phone, SSN, credit card) with LLM-backed detection for unstructured PII (names, addresses).

All PII is replaced in-place with bracketed placeholders — e.g. [EMAIL], [NAME] — and exact character offsets of every detection are returned so your downstream system can audit or highlight redacted spans.

The API is stateless, requires no authentication key in MVP, and returns JSON. Average latency for text under 500 tokens is < 800 ms end-to-end (regex: < 1 ms, LLM pass: ~700 ms on Claude Sonnet).

2. Base URL

https://<your-vaultflow-host>
Replace <your-vaultflow-host> with the hostname where the gateway is deployed. In local dev this is http://localhost:8000.

All paths below are relative to the base URL. The API serves only HTTPS in production.

3. Endpoints

POST /redact
Detect and redact all PII from a text string.

Request headers

HeaderRequiredValue
Content-Type Yes application/json

Request body

FieldTypeRequiredDescription
text string Yes The raw text to scan. Must be non-empty and not all whitespace. No length hard cap in MVP; keep under 8 000 tokens for best LLM latency.

Example request

curl -sS -X POST https://<host>/redact \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Hi, I am Jane Doe. Email me at jane@acme.com or call 415-555-0192. SSN 123-45-6789."
  }'

Response body (200 OK)

FieldTypeDescription
redacted_text string The original text with every detected PII span replaced by its placeholder token.
detections array<Detection> Ordered list of detected PII spans (sorted by start offset ascending).

Detection object

FieldTypeDescription
type string PII entity type. One of: EMAIL, PHONE, SSN, CREDIT_CARD, NAME, ADDRESS.
start integer Inclusive start character offset in the original text (0-indexed).
end integer Exclusive end character offset in the original text. Span is text[start:end].
source string regex — detected by pattern matching; llm — detected by the Claude LLM pass.

Example response

{
  "redacted_text": "Hi, I am [NAME]. Email me at [EMAIL] or call [PHONE]. SSN [SSN].",
  "detections": [
    { "type": "NAME",  "start": 9,  "end": 17, "source": "llm"   },
    { "type": "EMAIL", "start": 32, "end": 45, "source": "regex" },
    { "type": "PHONE", "start": 55, "end": 67, "source": "regex" },
    { "type": "SSN",   "start": 73, "end": 84, "source": "regex" }
  ]
}

4. PII Entity Types

    

      EMAIL
      PHONE
      SSN
      CREDIT_CARD
      NAME
      ADDRESS
    

    

      
TypePlaceholderDetectorPattern / Notes

      

        EMAIL
        [EMAIL]
        Regex
        RFC-5321 local-part @ domain. e.g. alice@example.com
      

      

        PHONE
        [PHONE]
        Regex
        
          US numbers — formatted: (415) 555-0192, 415-555-0192,
          415.555.0192; raw 10-digit: 4155550192;
          optional +1 country code prefix.
        
      

      

        SSN
        [SSN]
        Regex
        US Social Security Numbers in dashed format: ###-##-####
      

      

        CREDIT_CARD
        [CREDIT_CARD]
        Regex + Luhn
        
          13–19 digit sequences (with optional spaces or dashes), validated with the
          Luhn algorithm to minimise false positives. Covers Visa, Mastercard, Amex,
          Discover.
        
      

      

        NAME
        [NAME]
        LLM (Claude)
        
          Full personal names detected in context. Handles first-only, first+last,
          titles (Dr., Mr., Mrs.), and non-Western name patterns.
        
      

      

        ADDRESS
        [ADDRESS]
        LLM (Claude)
        
          Physical street addresses. Includes house number + street, city, state, ZIP.
          Does not flag country names alone.
        
      

    

    

      Overlapping detections are resolved automatically. The gateway merges spans
      so no character is redacted twice. Regex detections take precedence over LLM
      detections when spans overlap.
    

  


  
  

    
5. Detection Pipeline

    
Every POST /redact call runs two passes in parallel:

    

      
PassWhat it catchesLatency

      

        Regex
        EMAIL, PHONE, SSN, CREDIT_CARD
        < 1 ms
      

      

        LLM (Claude Sonnet)
        NAME, ADDRESS
        ~500–900 ms
      

    

    

      Results from both passes are merged into a single ordered list of
      non-overlapping Detection objects. The merged list is used to
      rewrite the text and is returned in the response.
    

    

      The gateway fails closed: if the observability log write fails (e.g. Convex
      unavailable), the request returns 502 rather than silently
      skipping the audit trail.
    

  


  
  

    
6. Error Codes

    

      
StatusConditionResponse body

      

        200
        Success
        { "redacted_text": "…", "detections": […] }
      

      

        422
        Validation error — text is missing, empty, or all whitespace
        { "detail": [{ "msg": "text must not be blank", … }] }
      

      

        502
        Upstream error — audit log write to Convex failed
        { "detail": "redaction log write failed" }
      

    


    
Handling errors

    
Treat 422 as a client error (fix the request). Treat 502
    as a transient server error — retry with exponential back-off. The gateway does not
    partially redact: if you receive a non-200, the original text was not modified.

  


  
  

    
7. Full Examples


    
Redact a patient intake note (healthcare / HIPAA context)


curl -sS -X POST https://<host>/redact \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Patient: Maria Santos, DOB 1988-03-14. SSN 987-65-4321. Contact: maria.santos@gmail.com, (312) 867-5309. Address: 400 N Michigan Ave, Chicago, IL 60611."
  }' | python -m json.tool



// Response

  "redacted_text": "Patient: [NAME], DOB 1988-03-14. SSN [SSN]. Contact: [EMAIL], [PHONE]. Address: [ADDRESS].",

    { "type": "SSN",     "start": 42,  "end": 53,  "source": "regex" },

Python (requests)


import requests

resp = requests.post(
    "https://<host>/redact",
    json={"text": "Call John Smith at john@example.com"},
    timeout=10,
)
resp.raise_for_status()
data = resp.json()
print(data["redacted_text"])   # "Call [NAME] at [EMAIL]"
print(data["detections"])      # list of Detection dicts


    
JavaScript / Node (fetch)


const res = await fetch("https://<host>/redact", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Billing card: 4111 1111 1111 1111" }),
});
const { redacted_text, detections } = await res.json();
console.log(redacted_text);   // "Billing card: [CREDIT_CARD]"

8. SDK / Library Quickstart

    

      No dedicated SDK yet — the API surface is small enough that a thin wrapper is
      all you need. Here is a reusable Python helper:
    


import httpx   # pip install httpx

class VaultflowClient:
    def __init__(self, base_url: str):
        self._base = base_url.rstrip("/")

    def redact(self, text: str) -> dict:
        r = httpx.post(
            f"{self._base}/redact",
            json={"text": text},
            timeout=15.0,
        )
        r.raise_for_status()
        return r.json()

# Usage
client = VaultflowClient("https://<host>")
result = client.redact("Jane Doe, SSN 123-45-6789")
print(result["redacted_text"])   # "[NAME], SSN [SSN]"
